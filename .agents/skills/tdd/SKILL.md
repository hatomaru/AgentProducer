# TDD (テスト駆動開発) スキル

新機能の実装やバグ修正を行う際は、以下のTDDのサイクルを厳密に守ってください。

1. **Red (失敗するテストを書く)**: 実装したい機能に対するテストを最初に書きます。このテストは失敗する（またはコンパイルエラーになる）必要があります。
2. **Green (テストを成功させる)**: テストをパスさせるための最小限のコードを書きます。この段階では過剰な設計（オーバーエンジニアリング）は避けてください。
3. **Refactor (リファクタリング)**: 振る舞いを変えずに、コードの構造、可読性、パフォーマンスを改善します。リファクタリング後もすべてのテストがパスすることを確認します。

## ガイドライン
- テストは焦点を絞り、高速で、独立したものにしてください。
- テスト名は期待される振る舞いを明確に説明するものにしてください。
- 成功したGreen/Refactorのサイクルごとにこまめにコミットしてください。
- 失敗しているテストをパスさせるために必要な場合のみ、プロダクションコードを書いてください。
